# Legado 书源工具链：长期判据

本文件只回答“为什么这样做、怎样避免重犯”。当前硬约束以 `AGENTS.md` 为准，用户用法以
`README.md` 为准，待办以 `TODO.md` 为准，具体实现与测试是最终证据。历史编号保留是为了不让
现有指针断掉；编号之间的空位不补。

只收能从当前代码、测试或上游源码复核，且会改变下一次实现决策的内容。删掉阶段名、过程记录、
一次性计数、用户讨论原话和已由代码表达的实现说明。每节按“症状 → 根因 → 判据”写，末尾的
`→` 只指向对应的项目规矩。

## 一、规则文本不能被当成普通 CSS 解释

本地验证如果把 `class.`、`tag.`、`text.`、`@js:`、JSONPath、替换语法当成普通 CSS，空结果
就会被误报为源失效。**结论是不要有第二套解释器**：规则一律交给 App 引擎执行，Python 侧
只在提示词取景框上认 `class.` / `id.` / `tag.` 三种前缀，认不出就退回整篇。曾经的本地回放器
就是这样退场的——它对不支持的语法返回原因，但「我们不会算」这个状态本身就不该存在于
验收链路上。

→ 这支撑 AGENTS #3、#4：验收由引擎完成，工具不会算与源失效必须分开；
`core/repair/suggest.focus_selector` 是唯一残留的规则文本解析。

## 二、静默失败：原因必须到达用户

跨层问题常表现为“请求成功但界面不变”：异常被吞、字段被响应模型裁掉、类型或空值语义漂移、
条件不满足却直接 `continue`。每条无法验证、跳过和降级路径都要保留原因；记录发生了什么与
由此推断什么必须分开，不能用同一个开关同时控制。

→ 这支撑 AGENTS #4：原因不能在服务端、响应模型或显示层被压成一句笼统状态。

## 四、类型判定不能信声明值

`bookSourceType`、分组和健康标签都可能是已有结论，不是独立观测。类型判定只能使用页面、规则
和上游引擎可复核的信号；证据不足就保持原值并说明原因，不把默认值重新投票给自己。

→ 这是 AGENTS #11 在类型判定上的实例：派生结论不能回流成自己的判据。

## 五、URL 先规范化，再作为 key

跨表、跨库、缓存、去重和接口回填只要一侧使用原文 URL，就会出现“数据存在但一条都匹配不上”。
统一使用 `core.loader._normalize_url`，并在两侧都归一；前端收到的源 URL 与原始导出 URL 也不能
例外。关联改动必须有数量或分布对账，不能只看接口没有报错。

→ 这是 AGENTS #5：URL 身份的唯一口径在归一化函数，不在调用方。

## 十、核心层不反向依赖调用方

依赖方向应是 backend/services → core。共用判据和小函数上移到 core，不从 core 导入上层。

2026-09-30 复测：core 对 services 的惰性 import 归零——最后两处随修复循环按调用图退场。

→ 这条约束避免同一判据被调用层各写一份；删旧链时按调用者审计，不能按文件盲删。

## 十二、变异窗口内不做 Git 操作

变异测试会临时把源码改坏。`git add` 抓的是当时磁盘内容，可能把源码中间态和相反的测试一起
提交。变异前先提交可回退点或使用隔离 worktree；变异窗口内不 `git add`、不提交。等长替换要用
`python -B`，还原必须保留原始字节和行尾。

→ 已提炼为 AGENTS #14：变异验证与提交必须完全隔离。

## 十三、Teleport 组件内部样式不能依赖 scoped

Element Plus 的 dialog/drawer 内部节点被 teleport 到 `body`，组件的 scoped 选择器够不到它们；
`:deep()` 也不能补上不存在的 scope 属性。组件内部结构用不带 `scoped` 的局部样式块和组件前缀，
只有跨组件共用的样式才进全局文件。插槽里由本组件渲染的节点仍可使用 scoped。

→ 已提炼为 AGENTS #15：先判断节点归属，再决定样式作用域。

## 十四、App 调试的源身份必须可确认

App 调试按源 URL 查 App 库，不是接收一份任意源对象。新源或未保存改动必须经过明确的缺源/旧源/
可用预检；若要推送到 App，必须是用户主动操作并明确承担覆盖同 URL 源的副作用。比较双方规则时，
只比较调试实际使用且两边都稳定存在的字段，不用跨模型指纹硬比。

→ 调试、推送和源身份是三件事，不能用一次隐式写入掩盖前置条件。

## 十七、合并配置时只有 None 表示“没传”

默认值与本次覆盖合并时，`False`、`0` 和空字符串都可能是用户明确传入的值。不能用 `or` 判断
是否覆盖；应使用 `is not None`，并用成对测试区分“未传”和“传了空值”。

→ 这是所有“全局默认 + 本次覆盖”接口的通用判据。

## 十八、判定输入不能包含自己的派生结论

分组、缓存、指纹、报表和质量标签都是候选派生字段。若 A 的输出被写回 A 的输入，错误会自我
固化，下一轮再也纠正不了。审查判据时先清空派生字段再问：结论是否仍由原始观测成立？

→ 已提炼为 AGENTS #11。

## 十九、先确认字段存在，再读它

不存在的字段会形成永远不执行、却看起来像有效信号的死分支。发现可疑字段时，先查上游模型、
实际数据和调用次数；删除死分支时同步删除钉住旧行为的断言，避免测试继续把死代码伪装成能力。

→ 已提炼为 AGENTS #12：读不到材料不等于材料不存在。

## 二十三、同一件事可能有多个入口

Web、调试抽屉和批处理可能各自调用不同提供方。替换实现时必须同时检索旧
符号、输入输出形状、读写数据路径和模块名；每个残留调用者都要能说明为何保留。跨入口结果体
要同形，但“同形”不能代替“同一判据”。

→ 这是供应方迁移和跨语言对接时最容易漏掉的边界。

## 三十一、数字必须带环境与口径

计数、耗时、分布和性能结论至少同时说明环境、数据路径或库、样本/快照时间和计算口径。缺一项
就不要把数字写进长期文档；无法复核的数字只能作为 `git log` 中的历史证据，不能作为现行决策
依据。

→ 已提炼为 AGENTS #23③。

## 三十二、外部导入与用户编辑不是同一条写路径

外部导入默认只保留系统允许的用户标签和库内已知标签；用户主动编辑才允许创建新标签。过滤应放在
导入边界，不能把底层保存接口收紧到连用户编辑也受影响。

→ 同一张表由多条路径写入时，规则必须按路径定义。

## 三十四、重复源合并必须可回滚

合并判据以站点身份和行为指纹为准，不因名称相同就合并，不跨站点提供隐式逃逸口。写接口必须
原样返回真正新增的标签、旧备注和被软删除成员，使撤销不依赖最终状态猜测；软删除应在吸收信息
之后执行。

→ 删除与吸收信息的动作必须在同一条可审计写路径中完成。

## 三十五、展示名不是源身份

名称清洗只能改展示名，不能改 `source_url`。名称变化若参与 fingerprint，就必须承认会使派生缓存
失效；低置信度只给建议。不要复用会覆盖标签或备注的通用保存接口做专用撤销。

→ 身份字段、展示字段和派生缓存的职责必须分开。

## 四十六、界面文案说状态和动作

用户界面回答“现在是什么、下一步做什么”，不解释实现机制。一个概念只用一个词；术语表和机检
规则在 `tools/check_copy.py`，断言在 `tests/test_copy.py`。注释可以精确，但不能把内部术语带进
用户文案。

→ 已提炼为 AGENTS #18。

## 四十七、性能结论必须实测

没有环境、样本和测量过程的耗时估算不是证据。性能决策先跑最小真实样本，再报告分布和边界；不
知道就写未测，不用看似具体的乘法替代测量。

→ 这是 §三十一 的性能实例。

## 五十一、接 App 接口前先查完整能力清单

先读上游端点、权限、书架约束、事件流和批量能力，再决定是否复刻。对账按事件中的源身份归一，
不能把返回行数当源数；接口形状、来源字段和备份/覆盖副作用都要有不联网的契约测试。

→ 上游已有能力优先复用，测量口径必须与接口返回形状一致。

## 五十二、状态词表改名必须迁移存量

健康档位按下一步动作划分；当前公开档位以 `core/models.py` 为准，内部异常原因不自动变成用户
档位。改名时只替换存量字符串，不顺手重算状态；锁定状态也要换词。词表映射放在
`core/tags.py`，迁移测试覆盖旧词、锁定行和无 checks 行。

→ 已提炼为 AGENTS #17；本节不重复档位枚举。

## 五十三、批量结论必须可断点复用

错误要带 root cause；**不能以「全量跑完且进程没崩」证明环境正确**。

→ 批量测量的可复用单位是带来源和原因的单条记录，不是一个最终数组。

## 五十四、多段链路的结论必须带 stage

搜索、详情、目录和正文是不同阶段；失败要标明 stage，不能把“搜索没结果”和“正文取不到”塞进同一
个无来源状态。共享预算按每源计算，不能每个阶段各自重置。

→ 用户必须能从结论知道下一步修哪一段。

## 五十五、能力缺口先查上游，再查库内分布

类型、正文后处理、WebView 和脚本等能力不能凭字段名推断。先查 App 真正读取的字段，再按字段
非空和实际调用统计管理库；两边证据不足时不新增判据、不扩展出口。用户意图与页面事实不能互相
覆盖。

→ 没有可观测信号时，增加分支只是把一个猜测换成另一个猜测。

## 五十七、摘进主干的内容不应留下活分支

内容经过 cherry-pick 或手工适配落入主干后，原分支不再是可合并的事实来源；继续保留会让旧基线、
旧文案或旧适配在未来合并时重新进入。主干内容以当前提交为准，历史依据留在提交记录。

→ 已提炼为 AGENTS #19：落地主干后删除已摘内容的分支。

## 五十八、规则地址和取值末段不能按猜测处理

规则生成的 URL 先剥掉尾部 `,{json}` 选项，再做绝对地址和请求；选项属于 App 行为，不属于网络
地址。取值规则末段的 `text`、`html`、属性名和动作不能当 CSS 标签；列表规则与取值规则要走不同
分支。无法区分时保留原因，不静默取空。

→ 这是“把工具的问题说成源的问题”的典型边界，见 AGENTS #20、#21。

## 五十九、JVM 调试通道的边界由 App 能力决定

JVM 调试可以复用 App 的事件流和规则引擎，但设备才拥有用户真实网络、登录流程和最终环境。通道设计
先按上游能力清单划分“本机可做”和“只能 App 复检”，不要用本地复刻去填补能力缺口。

→ 调试能力的边界来自上游语义，不来自接口名字。

## 六十五、JVM 直起的环境快照必须可追溯

Gradle、直起、常驻必须共用同一份可验证的环境描述，缺失就显式失败（字段与检查在 `jvm_direct.py` / `jvm_env.py`）。

→ “启动成功”不等于“运行了当前代码和当前参数”。

## 六十六、常驻 daemon 的优化不能牺牲隔离

profile 按请求或所有权隔离、请求间清浏览器状态、停止要验证进程真的退出；判死只能依据进程身份与存活信息，不能依据端口行为（见 `jvm_validate_daemon.py`）。

→ 常驻是加速手段，不是放宽资源生命周期的理由。

## 六十七、环境 readiness 不缓存，常驻引擎按需准备（B2）

readiness 依赖源码、启动器、Gradle 用户目录、SDK 内容和进程环境；维护不完整的失效键会把旧的「可用」结论留给新配置。当前直接每次探测，`cost_sec` 记录本次实际成本；打开检查页不启动常驻 JVM，真正执行时再按批准备。

实测（2026-10-07 本机）：readiness 冷探测 0.25–0.83s，常驻引擎热复用 0.0055s；把启动放在执行链能保留性能收益，又不让只查看环境的请求产生隐藏进程。

→ 环境检查要新鲜，常驻是执行阶段的加速手段，不是检查页的副作用。

## 六十一、跨语言结论只能有一个编码出口

Kotlin 与 Python 之间的 JSON 形状必须由一侧编码、另一侧入口做显式类型闸门；`null`、布尔、数字、
嵌套对象不能依赖默认 `toString()`。两侧各有不联网形状测试，复制的词表或常量必须逐词契约比对。

→ 入口防御应放在边界，不能让前端显示层把错误洗成“未验证”。

## 六十三、登录态从 profile 取得，不代用户登录

浏览器 profile 中已有的 cookie 可以作为调试环境输入；工具不替用户完成验证码、短信、风控或登录
流程。缺登录态应明确标成需要人工预热，并区分“未登录”“浏览器没拿到 cookie”和“源规则失败”。

→ 登录态是环境证据，不是工具可以代填的业务动作。

## 六十八、动作和结果必须在同一屏

长任务的入口应靠近它写入或展示的结果；本次运行参数只作用于本次任务，不要把执行动作藏在全局
配置页，也不要让弹窗重新询问已经由入口确定的范围。用户看到的状态、结果和失败原因必须来自同一
条任务链。

→ 这是 AGENTS #10、#13、#18 在任务交互上的共同应用。

## 六十九、测试不能把被测步骤整体打掉

网络、Gradle 和子进程可以替换；被测的导出、参数组装、真实库读写和结果落库不能整体 mock。至少
有一条真数据小样本测试穿过目标步骤，否则“有测试在跑”不能证明端点能用。

→ 测试替换的是外部代价，不是被验证的行为本身。

## 七十一、长期注释只写代码读不出来的事实

注释和长期文档都要回答读者、不可从代码直接读出的机制、以及保质期三个问题。阶段名、进度、当前
行数、一次性耗时和已删除符号不进长期注释；约束型理由若会阻止重犯才保留，并指向唯一证据来源。

→ 已提炼为 AGENTS #23。

## 七十二、健康档位区分“谁跑不了”与“源坏了”

引擎、网络、登录态和源规则是不同证据来源。引擎自身缺绑定、环境异常或无法回放时，不能把源判坏；
健康档位由 `core/jvm_health.py` 和 `core/models.py` 的现行映射产生，异常原文和 stage 继续保留。

→ 结论必须带证据来源，工具能力不能投票否定源。

## 七十三、离线推断不是 App 真实验收

候选、样本比对与 DOM 大纲都属于**离线推断**：它们加速「下一步改什么」，
而 App 引擎或真机才是需要上游语义、WebView、登录态的验收来源。两者同屏时必须标明来源，
不能用离线推断的空结果覆盖引擎结论。

→ 推断是加速手段，不是第二份健康事实。

## 七十四、任务锁跟着执行线程，测试不写真库

测试用隔离库或明确的 fixture，不把临时结果写进用户管理库。

→ 任务生命周期由执行者负责，界面只是观察者。

## 七十五、matched_html 是证据，不是结论

`matched_html` 的形状由 Kotlin 侧编码器和 Python 侧 `matched_map` 共同约定，键是 URL 与段名；
每段按自己的取值规则或列表规则处理，不能把一个段的 DOM 借给另一个段。补回的 DOM 只帮助解释
取值，不能改变已产生的判定。

→ 证据回填必须保持来源、作用域和判定三者分离。

## 七十七、生成失败必须保留真实原因

“工具认不出页面”“没有可用材料”“规则不支持”“验证未完成”和“源本身无结果”是不同状态，
不能统一返回“生成失败”。生成结果与验证结果分开返回；生成成功但暂时无法验证时，保留源并给下一步
动作。

→ 这是 AGENTS #4 的快速生成实例。

## 七十八、同一界面动作的多个入口必须同形

Web、单源调试和批量任务如果表达同一个动作，返回体应共享一个 builder 或契约测试；共享形状
不代表可以各自判定。前端不能通过 `undefined`、空数组或默认文案隐藏某个入口的错误。

→ 同形是接口契约，统一判据才是事实来源。

## 七十九、层级判定必须有证据出处

页面层级、源声明能力和引擎观察结果是不同轴。每条 L1–L4 结论应能指向原文或观察到的请求，前端只
展示后端判定；无法取得材料时返回缺材料原因，不能把“没看到”写成“没有”。

→ 结论必须可反驳，材料缺口不能变成事实断言。

## 八十、换提供方要检查所有入口

替换执行器（本地执行体、JVM 引擎或浏览器桥）时，必须同时检查 Web、批量任务、测试和数据迁移。
生成验证走 `core.jvm_debug.verify_generated`。反例（2026-09-30 收口）：有一条链在被删的函数上
留了惰性 import，8 天里每次调用都直接 ImportError——迁移只按入口宣布完成，就会留下这种
「还在用」的假象。

→ 供应方迁移要按调用图和数据路径收尾，不按单个入口宣布完成。

## 八十一、层级判定需要足够材料

页面引用的同站脚本可能包含解密和接口逻辑；只看 HTML 会把 L3/L4 静默低估成 L2。脚本抓取要有
同站、数量、大小和跳过原因边界；材料没取到时标成缺材料，不等同于脚本不存在。

→ 观察范围不足时只能降低置信度，不能制造否定事实。

## 八十二、正文规则同时受类型意图与页面事实约束

类型是用户要把内容当成小说、漫画、听书还是下载源的意图；页面层级是当前材料的事实。两者冲突时
对账并说明，不要静默修改用户意图；高层级需要脚本、接口或 WebView 时，不生成看似能运行的普通 CSS
规则。

→ 可推导的状态才自动推导，用户意图必须显式保留。

## 八十四、接口规则必须来自观察到的请求

页面 JS 发出的 XHR/Fetch 才是接口证据；不要从缺失 HTML 或脚本文本猜 URL、方法和 body。响应可能是
JSON、HTML 或 JSON 信封中的 HTML 片段，必须按实际形状选择 JSONPath 或 CSS 规则；埋点和统计请求
不能因“也是 JSON”被选为业务接口。所有猜测字段写入附注。

→ L4 生成链的材料是网络观察，不是静态猜测。

## 八十六、代理要覆盖两条取数栈

源 header 服务 OkHttp，浏览器桥服务真实浏览器；两者都需要代理配置。App header 按上游要求使用
JSON，不把行式 header 当作通用格式；代理注入必须有可观察的生效测试，配置失败不能静默退回直连。

→ 配置写入点与消费点必须成对验证。

## 八十七、删半条链路前先查读者

一个模块可能同时包含执行体和被其他链路复用的纯判据。删除前按符号、调用者、数据资产和测试分组；
先迁移读者，再删执行体。旧缓存、旧任务、旧设置和旧前端入口都是数据/接口读者，不能只 grep 文件名。

→ 删除边界由调用图决定，不由文件边界决定。

## 八十九、L4 靶子与响应形状不能靠库内推断

能直接生成搜索规则的源不一定需要 L4；真正需要接口观察的靶子要通过浏览器扫描或外部输入得到。
抓到请求后还要验证响应形状：JSON 信封装 HTML 片段不能直接按同构 JSON 数组解析。材料不足时停止
当前生成分支并把原因带到用户眼前，不要降级产出空源。

→ L4 的两个边界都是材料闸门：靶子选择不能自证，响应解包不能静默跳过。

## 九十、快照对拍差异先归三类，落不进去的才是真漂移

对拍（`core/jvm_runtime_snapshot.compare`）比的是「Gradle 任务声明」与「真实 JVM 自述」，两侧
语义不同，有差异 ≠ 有漂移。实测（2026-09-26，refresh / gradle / validate_daemon / direct 四份
报告）差异只来自三类：① **不存在的 classpath 项**——Gradle 组装实际 classpath 时会跳过不存在
项（KSP 空变体目录时有时无），执行态检查只钉 jar/zip；② **worker 注入项**——Gradle test
worker 自带 `-Dheadless` / `-ea` / 编码区域 / `worker.tmpdir` / `gradle-worker.jar`，declared
里没有是正常的，反过来 declared 的 `-Xmx` / `--add-opens` 没出现在 actual 里才是漂移；
③ **逐次任务的输入**——`LEGADO_APPSERVICE_ARGS` 指向每次运行的参数文件（目录用完即清），冻结在
dump 环境里就是静默继承：直起 JVM 沿用冻结值读不到参数、整条调试链 0 事件（同日实测，修复后
恢复 77 事件），`run_direct` 必须显式注入本次路径；daemon 不受影响，它的 args 由客户端读了走
协议传，进程内从不读这个文件。

→ dump 冻结的是「可复用的运行时描述」，逐次任务的输入必须走显式通道；读对拍报告先分三类，第四类差异才值得动手。

## 九十一、判据散在几处，界面就会把同一件事说三遍

一次调试里「缺什么」出现三遍、动作互相覆盖：口袋漫画那一步同时显示「缺规则 / 缺节点 /
缺运行时材料」，而三者有先后（规则没写，取材料是白取），用户不知道该点哪个。根因不是文案
啰嗦，是**判据与呈现混在一起**——组件内诊断、unknown 出口、下一步动作、证据摘要、AI 门槛
各从自己那半材料出发说一句完整的话，谁也不知道别人已经说过。

实测（2026-10-03）：那一步的首屏从 3 条缺口 + 3 段机制说明收敛为 1 条现状 + 1 个主动作。

→ 已提炼为 AGENTS #24：同一件事的判据只能一处，界面一次只说一条。

## 九十二、同一个运行的观测口写了两份，它们必然漂（观测收口 D2）

症状：同一个任务的「在跑」状态有两个来源——明细弹窗与时间线各每 2 秒拉一个端点，返回同一批
字段（status/phase/progress/total），而 `JobTimeline` 把这份状态 `emit("state")` 出来却**全仓
没有监听者**；调试则是同步长轮询，等待期只剩一个前端本地秒表（刷新归零，`--reload` 之后登记
随进程一起消失）。

四处代价都不是"报错"而是"看起来正常"（2026-10-09 实测）：① SSE 每帧推整行（含冻结的 `payload`），
终态帧 467,863 字节、运行中每帧约 105 KB，而订阅者只要几个数；② 成功清场把**事件账本**一起删了
——时间线终态只能读 `result_json` 里的 500 条尾巴，跑成功的批看不到开头；③ 失败清单每拍重扫各块
`results.jsonl`（读那一块结果时手里就有）；④ 保留策略两套（目录个数上限 vs 任务行 TTL），按个数
删会让行还在、时间线空了。

另有一条前提值得记：调试引擎**本来就逐条 flush**（`DebugService.kt` 写着"崩了/超时也要留下已
收到的那部分"），缺的只是"边跑边读"——`subprocess.run` 读完才解析的写法，让"无产物可读"看起来
像引擎的限制。

→ 已提炼为 AGENTS #25：运行观测只有一条读法、一个生产者，界面不许自己取数。
