# 书源持续合并与淘汰管理设计

## 目标与范围

本设计面向 Legado 外部书源的持续合并与淘汰。目标是在保留「可用、待验证、需代理复检」完整候选库的前提下，安全接收外部书源，避免外部规则直接覆盖已验证规则，并让失效书源的淘汰过程可追溯、可回退。

本设计不改变 Legado 的书源 JSON 格式；管理元数据独立保存，导入 Legado 的 JSON 仅是候选库的派生产物。

不在本期范围内：书源规则自动修复、网页管理界面、自动绕过登录或反爬验证。

## 现状问题

现有工具已经具备合并、校验、分组、清洗和报告能力，但主文件与中间产物的职责有重叠，外部同 URL 更新采用覆盖策略也会直接改写主库。此外，校验缓存仅按 URL 复用，规则变更或缓存过期后可能沿用旧健康状态；重复整理还会累积 `[原分组]` 和测试命中标记。

## 总体模型

书源按以下生命周期流转：

```text
外部文件
  -> 导入批次（原文件、来源、导入时间）
  -> 暂存区（清洗、归一化、去重、规则指纹比对）
     ├─ 新 URL：待校验
     ├─ 同 URL + 同规则：忽略并记录
     └─ 同 URL + 规则变化：待审，不覆盖候选主库
  -> 校验（常规、代理复检、深度审计）
  -> 候选主库
     ├─ 可用
     ├─ 待验证
     ├─ 需代理复检
     ├─ 待审
     └─ 已淘汰
  -> 导出 Legado JSON 与管理报告
```

候选主库是唯一事实来源。`final_all.json`、`checked.json`、`organized.json` 等不再承担主库身份，而是由候选主库按需要导出的结果文件。

## 文件与元数据职责

建议新增独立管理目录；具体实现可用 Python 标准库 SQLite，避免引入第三方依赖。

| 内容 | 建议位置 | 作用 |
|---|---|---|
| 外部原始文件 | `imports/raw/` | 保留导入批次，便于回溯 |
| 暂存与冲突项 | 管理台账 | 支持校验、审批和差异查看 |
| 候选书源规则 | 候选库 JSON | Legado 导出的规则来源 |
| 来源、指纹、状态、检查时间、失败次数、审批历史 | 管理台账 | 驱动合并与淘汰决策 |
| 可导入 Legado 文件 | `exports/` | 只读派生产物 |
| 检测缓存 | `check_cache/` | 加速校验，不作为状态真相 |

每个书源管理记录至少包含：规范 URL、当前规则指纹、首次导入批次、最近来源批次、当前状态、最近校验时间、最近校验结果、连续明确失败次数、规则变更待审标记和处置记录。

## 合并规则

1. 外部文件必须先清洗字段类型，再进入暂存区；禁止直接写入候选主库。
2. URL 归一化后首次出现的书源，建立待校验记录。
3. URL 相同且规则指纹相同的书源，不重复入库，只记录其再次出现的导入批次。
4. URL 相同但规则指纹不同的书源，建立待审冲突记录，不自动替换候选主库。
5. 审批通过后，以外部规则更新候选主库，并强制重新校验；审批拒绝后保留原主库规则及拒绝原因。
6. 名称变化不是唯一性依据；名称作为显示字段和人工审查辅助信息。

## 校验与淘汰规则

校验缓存必须同时满足「URL 相同、规则指纹相同、未超过状态对应的有效期」才可复用。规则变更后立即失效，不得沿用旧结果。

建议有效期：可用 14 天、待验证 7 天、需代理复检 7 天、明确失败 7 天。深度审计独立记录其深度和时间，不以浅探测结果替代。

状态处置如下：

| 校验结果 | 状态 | 处置 |
|---|---|---|
| 域名与搜索可用 | 可用 | 保留并按有效期复检 |
| 403、验证码、登录墙 | 待验证 | 保留，人工或后续复检 |
| 代理环境下才可检查或疑似网络限制 | 需代理复检 | 保留，代理复检 |
| DNS 失败、域名注销、稳定的连接失败或搜索明确无结果 | 待复检 | 记录首次明确失败 |
| 间隔至少 7 天的两次明确失败 | 已淘汰 | 从候选导出中排除，保留历史记录 |

403、验证码、限流、代理配置错误和超时不计为明确失败，不能触发淘汰。

## 面向 Legado 的分组与标记

`bookSourceGroup` 只承载稳定、使用时有价值的信息：内容类型、管理状态和必要业务标签。例如：

- `📖小说,可用`
- `📖小说,待验证`
- `📖小说,需代理复检`
- `📖小说,待审`
- 附加标签：`R18`、`正版`、`原创`、`仅发现`

不写入分组或系统管理的 `bookSourceComment`：

- `命中《书名》` 等测试命中标记；
- 历史健康度、失效、超时等临时诊断标记；
- 多次整理累积的 `[原分组]`。

测试命中书名仅保留在管理台账和管理报告的证据列中，用于解释星级或深度校验结论；不再以书源标记展示。星级可保留在报告中用于排序，但不写入 `bookSourceGroup`，以免质量检测变化干扰日常分组。

## 导出与日常操作

日常流程为：导入外部文件 -> 查看待审和待校验列表 -> 执行常规校验 -> 必要时执行代理复检 -> 审批冲突 -> 导出候选库 -> 查看淘汰与复检报告。

导出应至少提供两类文件：

1. 完整候选导出：可用、待验证和需代理复检，供完整备份或进阶使用。
2. 日常精简导出：仅可用书源，供追求搜索速度的 Legado 实例使用。

已淘汰和待审书源均不进入默认 Legado 导出。每次导出保留带时间戳的快照，最近若干版本可回退。

## 验收标准

1. 外部同 URL 规则变化不会自动覆盖候选主库。
2. 规则变化能使对应校验缓存失效并触发重新校验。
3. 待验证和需代理复检书源始终保留在完整候选库中。
4. 只有两次间隔至少 7 天的明确失败才会自动淘汰。
5. 导出的 `bookSourceGroup` 和系统管理的备注中不存在 `命中《》`、旧失效标记或重复 `[原分组]`。
6. 每个导出源可追溯到来源批次、规则版本和最新校验结论。
